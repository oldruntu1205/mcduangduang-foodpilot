# 中文约束解析规则

用户不会说「结构化约束」，会说"我们五个人，别超过 160，有个不吃牛的"。这份文件规定怎么把话翻译成槽位，以及哪些地方必须追问。

## 一、六个槽位

| 槽位 | 常见说法 | 归一化 |
| --- | --- | --- |
| 人数 | 我们5个人 / 我和同事 / 4个人一起 / 团建8人 | 整数 n。**"我和同事4个" = 5 人**（包含自己） |
| 预算 | 160够了 / 人均30 / 别超过200 / 就200预算 | 元。**"人均"要乘人数**成总预算 |
| 就餐方式 | 到店取 / 送公司 / 堂食 / 开车过 | 外送 / 到店自取 / 堂食外带 / 得来速 |
| 地点 | 望京SOHO / 公司楼下那家 / 我家 | 地址或门店名 |
| 每人约束 | 一个不吃牛肉、有个不能吃辣、还要低热量 | 按人绑定；未点名时按"人数配额"处理 |
| 特殊 | 想吃鸡 / 不要饮料 / 加个甜点 | 软偏好 |

## 二、约束强度：必须先分清

这是最容易出事故的地方。同一个句子，可能是过敏，也可能只是不爱吃。

**判定为硬约束（零容忍）**：
- 出现"过敏""会难受""一点都不能""宗教""清真"
- 出现"不能吃""绝对不要"
- 语气强烈："千万别给他牛肉"

**判定为软约束（扣分项）**：
- "不太喜欢""尽量别""能不吃就不吃""随便啦"

**拿不准就问**，一句话解决：

> 「不吃牛肉是过敏，还是单纯不爱吃？过敏的话我按零容忍处理，整桌重排。」

默认按**硬约束**处理——安全优先，宁可方案丑。

## 三、人数与约束数量不匹配

用户说"5 个人，一个不吃牛肉、一个不能吃辣"，只点名了 2 条约束，剩下 3 人无约束。

处理规则：
1. 已点名的，绑定到具体人（能对上名字就绑名字）
2. 未点名的，生成占位人名（如"第 3 位""第 4 位""第 5 位"），**并说明这是我编的占位**
3. 不要让无约束的人"随便"——方案里给他兜一个大众口味，别给他最冷门的

若用户说"剩下都随便"，则其余人按 `Person()` 无约束处理，求解器会自动给他们价格/热量适中的选项。

## 四、热量约束

| 说法 | 处理 |
| --- | --- |
| 低热量 / 要减肥 / 控卡 | 默认 `lowcal600`（主餐 ≤600kcal） |
| 减脂 / 严格控卡 | `lowcal500` |
| 给了具体数字（"不超过 500 卡"） | 用该数字 |
| "热量别太高"（模糊） | 用 600，并在方案里注明"按 600kcal 上限处理" |

**重要**：热量上限只管主餐。共享小食是均摊的，脚本会在 `checks` 里提示"均摊后约 xxx kcal，建议不分小食"，要把这条转述给用户。

若接口没给热量，脚本用经验值估算并标 `kcal_source=estimate`。输出时必须说明"热量为估算"，不能当营养建议。

## 五、忌口类别的映射

用户说的是肉，脚本要的是 `meat` 字段：

| 用户说 | 标志 | 说明 |
| --- | --- | --- |
| 不吃牛肉 | `nobeef` | 巨无霸、吉士、安格斯、犇、培根双层牛都算 |
| 不吃鸡肉 | `nochicken` | 板烧、麦乐、鸡排、鸡腿 |
| 不吃鱼 | `nofish` | 麦香鱼、鳕 |
| 不吃猪肉 | `nopork` | 麦芬猪、火腿 |
| 不吃辣 | `nospicy` | 麦辣、香辣、麻辣 |
| 素食 | `veg` | 四类肉全排除 |
| 不吃海鲜 | 先按 `nofish` 处理，**并追问是否排除虾类产品** |

**坑**：「吉士」= cheese，但吉士汉堡是牛肉饼，必须归 `beef`。
菜名里不含肉类关键词但实际含肉的（如某些新品、联名款），脚本会标 `meat=unknown` —— **这类绝不能分配给有忌口的人**，必须回查 `query-meal-detail`。

## 六、预算口径

- "预算 160" → 总预算 160
- "人均 30"、"一人 30 左右" → 总预算 = 30 × n
- "别超过 200" → 总预算 200
- 有配送费时，**配送费算在预算内**（脚本的共享小食会自动为配送费留余地，但 `calculate-price` 复核时要再确认一次）

用户没说预算时，**必须问**。不要用"人均 30"替他假设。

## 七、追问话术模板

问一次，把缺的全问完：

> 好，5 个人到店自取。还差两个信息：
> 1. 预算是总共多少，还是人均多少？
> 2. 在哪家店 / 哪个位置附近？我好拉对应门店的实时菜单。

补充追问（仅在必要时用一句）：

> 不吃牛肉那位是过敏还是口味问题？过敏我按零容忍处理。

不要在开头就把六个槽位一次性列成问卷，**先从用户话里能读出来的先确认，剩下的一次问完**。

## 八、解析完要回读

解析结果必须回读一遍让用户确认，格式：

```
确认一下：5 人 · 到店自取 · 总预算 ¥160 · 望京SOHO店
  王磊  不吃牛肉（已按硬约束处理）
  李婷  不吃辣
  张敏  主餐 ≤600kcal
  陈昊、赵宇  无特殊要求
```

用户纠错成本远低于整桌重排的成本。

## 九、群聊回复的解析规则

`group_prompt.py parse` 用的是这套规则。它面对的不是规范输入，是这些东西：

```
1 王磊 不吃牛
李婷：尽量别辣
3、张敏 减脂 要严格控卡
收到
陈昊 随便
我不吃鱼
```

### 9.1 行的三种形态

| 形态 | 处理 |
| --- | --- |
| `编号 + 名字 + 约束` | 按顺序绑人 |
| `名字：约束` / `名字 约束` | 冒号或空白切分，第一段非约束词当名字 |
| 只有约束（`我不吃鱼`） | 名字缺失，按 `--names` 顺序补，并明确告知"这个名字是我补的" |

### 9.2 词表 + 结构匹配双层

词表永远补不全。人说「牛的不行」「牛肉我拒绝」，不会说「不吃牛肉」。

所以除了固定词表，还有一层结构匹配：**肉类字（牛/鸡/鱼/猪）+ 3 字内的否定词（不行/不吃/不要/不能/别/过敏/忌/拒绝/受不了）**，两个方向都扫：

- `牛.{0,3}不行` → 命中「牛的不行」
- `别.{0,3}牛` → 命中「别给牛」

### 9.3 特殊回复

| 回复 | 处理 |
| --- | --- |
| `同上` `一样` `+1` `跟他` | 复制**上一条**的约束，并在输出里标 `[同上]`，同时提示复制的是谁 |
| `随便` `都行` `没忌口` `不挑` | 无约束。不要擅自给它加偏好 |
| `收到` `好的` `哈哈` `ok` | 噪音，跳过，不算一份订单 |
| 纯表情 / 纯符号 | 跳过 |

### 9.4 软要求一律保守

`尽量别辣` `少辣` `能不放辣最好` 会被当成 `nospicy` 处理，并在输出里标「（软）」。

代价是少两个可选单品，收益是不会给怕辣的人点到麦辣鸡腿堡。**但必须在交付时说明这条是保守处理的**，让用户有机会放宽。

### 9.5 必须回读的四件事

解析完，把这四类信息原样转给用户，一条不漏：

1. 「同上」复制的是谁的约束
2. 哪个名字是按名单补的
3. 谁还没回（`--expect` + `--names` 才算得出来）
4. 哪一行没看懂被跳过了

**有人没回时，绝不替他假设"应该没什么忌口"。** 要么催，要么明确说"他按无约束配了，可能会点到他不吃的"。
